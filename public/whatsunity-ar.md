# WhatsUnity: منزل واحد. اشتراك واحد. عائلتك بالكامل مشمولة.

> **التعريف الأساسي**: يحوّل WhatsUnity كمبوندك السكني إلى مجتمع مترابط، آمن، ومُدار رقمياً بالكامل.

WhatsUnity هو نظام تشغيل سكني متعدد المستأجرين (Multi-tenant Residential OS) جاهز للإنتاج، تم تطويره بالكامل باستخدام Flutter و Dart 3. يوحّد المنظومة السكنية في منصة واحدة تشمل إدارة الكمبوند، ونظام مراسلة مزدوج (Appwrite Realtime و Telegram API)، وبوابات أمنية تعمل بدون إنترنت بنسبة 100%، ودوريات أمنية بنقاط تفتيش NFC، ودورة صيانة هندسية خماسية الأدوار تربط 9 أدوار تشغيلية في تطبيق فائق الأداء.

- **القيمة الجوهرية**: منزل واحد. اشتراك واحد. عائلتك بالكامل مشمولة.
- **المطور**: نورالدين العدوي (Noureldin Adawy) — مهندس برمجيات متكامل ومعماري أنظمة موبايل.
- **الرابط الرسمي**: [https://whatsunity.app](https://whatsunity.app?lang=ar)
- **المعمارية والتقنيات**: Flutter، Clean Architecture، Dart 3 (Sealed Classes بدون توليد كود)، SQLite Local Master، Appwrite Cloud BaaS، Telegram MTProto API، وتخزين سحابي مباشر عبر Cloudflare R2.

## 1. الملخص التنفيذي ومصفوفة المشكلات والحلول

تعاني الكمبوندات والمجمعات السكنية المغلقة والأبراج السكنية من اختناقات تشغيلية حادة:
1. **فوضى مجموعات الواتساب**: مجموعات غير منظمة تؤدي إلى إزعاج مستمر، واختراق خصوصية أرقام الهواتف، وضياع الإعلانات الرسمية، وانعدام أي توثيق لهويات السكان ووحداتهم.
2. **هشاشة الاتصال (المناطق الميتة أوفلاين)**: بوابات المجمعات، ومواقف السيارات تحت الأرض، وغرف الخدمات تعاني باستمرار من ضعف أو انقطاع شبكات 4G و Wi-Fi، مما يوقف الأنظمة المعتمدة كلياً على السحابة.
3. **تكاليف الاشتراكات الباهظة**: التسعير القائم على كل مستخدم أو كل باب يجعل الأدوات السحابية مكلفة جداً للمجتمعات السكنية.
4. **تفكك العمليات التشغيلية**: غياب الربط بين السكان، وأفراد أمن البوابات، والفنيين، والمشرفين، وإدارة الكمبوند.

### حلول WhatsUnity المبتكرة
- **منزل واحد.. اشتراك واحد**: يغطي الاشتراك الوحدة السكنية بالكامل، مما يسمح بإضافة جميع أفراد الأسرة دون أي رسوم إضافية.
- **جاهزية كاملة بدون إنترنت (Offline-First)**: معمارية SQLite Local Master تضمن استجابة فورية لواجهة المستخدم (0ms) واستمرار فحص تصاريح البوابات والدوريات حتى في حالة الانقطاع الكامل للشبكة.
- **محرك مراسلة مزدوج (Dual-Engine)**: بنية مراسلة مرنة تتيح باقة تيليجرام المجانية (بدون تكاليف قواعد بيانات سحابية) أو باقة Appwrite اللحظية فائقة السرعة للمجمعات الفاخرة.
- **حوكمة 9 أدوار تشغيلية**: توحيد السكان، وحراس البوابات، والدوريات، ورئيس الأمن، والمنسقين، والفنيين، والمشرفين، وكبير المهندسين، ومدير الكمبوند في منظومة واحدة.

## 2. المعمارية التقنية وحدود Clean Architecture

يلتزم المشروع التزاماً صارماً بمبادئ Clean Architecture وتدفق البيانات أحادي الاتجاه (Unidirectional Data Flow) مع استبعاد أي توليد كود خارجي (`build_runner` و `freezed` مستبعدان تماماً لصالح Dart 3 Native Sealed Classes و Pattern Matching):

### طبقة العرض (Presentation Layer)
- واجهات Flutter المصممة خصيصاً لدعم العربية (RTL) مع تأثيرات زجاجية وتجاوب كامل عبر الشاشات.
- آلات حالة نقية عبر Dart 3 Cubits / BLoCs تصدر سجلات حالة غير قابلة للتعديل (Immutable State Records).

### طبقة النطاق (Domain Layer - خالية تماماً من تبعيات فلاتر)
- كيانات نقية (Pure Entities) مع أنماط نتائج محكمة `Result<T, Failure>`.
- حالات استخدام مستقلة (Use Cases) مثل `IssueGatePassUseCase` و `TriageMaintenanceTicketUseCase`.
- عقود المستودعات (Repository Contracts) المجردة (`ChatRepository`, `GatePassRepository`, `MaintenanceRepository`).

### طبقة البيانات (Data Layer)
- مستودعات المزامنة المحلية وتنسيق التحديثات مع السحابة.
- قاعدة بيانات SQLite محلية كـ (Source of Truth) للعميل بسرعة استجابة تقل عن جزء من الثانية.
- محرك مزامنة في الخلفية (Background Sync Engine) يعالج العمليات غير المتزامنة ويعيد تسوية البيانات.
- واجهات Appwrite Cloud (قواعد البيانات، الـ WebSockets اللحظية، وإدارة الهوية).
- تخزين وسائط الحافة عبر Cloudflare R2 بروابط HTTP/3 موقعة مسبقاً من وظائف Appwrite الحسابية.

## 3. محرك المزامنة بدون اتصال (Offline-First Sync Engine)

### نموذج SQLite Local Master
في WhatsUnity، لا تنتظر واجهة المستخدم استجابة الخوادم السحابية:
1. **تعديل فوري**: كافة الإجراءات (إصدار تصريح، تحديث مهمة صيانة، تسجيل حضور) تُكتب مباشرة في قاعدة SQLite المحلية مع وضع `sync_state = 'dirty'`.
2. **استجابة 0ms**: ترتبط واجهات المستخدم بالقاعدة المحلية وتتحدث لحظياً دون مؤشرات انتظار معطلة.
3. **عامل المزامنة في الخلفية**: يفحص السجلات المعلقة دورياً، ويحزم التعديلات، ويرسلها بتزامن متفائل (Optimistic Concurrency) إلى Appwrite.
4. **تسوية التعارض**: تطبيق قاعدة (Last-Write-Wins - LWW) المعززة بإصدارات تدريجية (Incremental Entity Versioning).

## 4. بنية المراسلة ثنائية المحرك (Dual-Engine Messaging)

توفر المنظومة واجهة تجريدية `ChatRepository` تتيح التبديل السلس بين محركين:
1. **محرك Appwrite Realtime (الباقة الممتازة)**: اتصال WebSocket دائم، ومؤشرات كتابة لحظية، وتأكيدات قراءة، مع تحديثات فورية لأعضاء المجموعة.
2. **محرك Telegram MTProto (الباقة الاقتصادية المجانية)**: توجيه المحادثات والإعلانات العامة عبر بوتات تيليجرام الرسمية، مما يخفض تكلفة خوادم وقواعد بيانات الدردشة السحابية إلى 0$.

## 5. منظومة أمان البوابات وتصاريح الزوار المشفرة (Cryptographic QR)

- تصريح الزائر عبارة عن كود QR مشفر يحتوي على: رقم الوحدة، وهوية الزائر، والوقت المسموح، وتوقيع رقمي مجزأ.
- أجهزة الحراس على البوابات تفحص التوقيع محلياً عبر المفتاح المشترك في أقل من 50 مللي ثانية (Sub-50ms) بدون الحاجة إلى أي اتصال سحابي أو شبكي.
- منع الدخول المكرر وتتبع المركبات المتجاوزة للوقت المسموح محلياً مع المزامنة التلقائية فور توفر الشبكة.

## 6. دورة الصيانة الخماسية ومصفوفة الأدوار

تطبق المنظومة دورة صيانة صارمة لمنع الهدر والتلاعب:
1. **الساكن**: يرفع البلاغ مرفقاً بصور أو مقطع صوتي يوضح المشكلة.
2. **المنسق (Coordinator)**: يفرز الطلب، ويحدد الأولوية، ويوجهه للفني المختص.
3. **الفني (Technician)**: يقبل المهمة، ويبدأ مؤقت الإصلاح في الموقع، ويلتقط صوراً قبل وبعد العمل.
4. **المشرف (Supervisor)**: يعاين الإصلاح ميدانياً ويتحقق من جودة التنفيذ.
5. **كبير المهندسين (Chief Engineer)**: يراجع تكاليف قطع الغيار ويعتمد الفاتورة ويغلق البلاغ نهائياً.
